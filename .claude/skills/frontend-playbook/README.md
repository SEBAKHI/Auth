# frontend-playbook

مهارة (Agent Skill) تحمل دليلًا هندسيًّا لبناء واجهة أمامية (SPA) تعكس نظامًا خلفيًّا.

الدليل **عامّ ومستقلّ عن أي مشروع**. كل بندٍ فيه مُستخلَص من كودٍ شُحن إلى الإنتاج وقيسَ أثره — وأكثره من عللٍ **لم يكتشفها اختبارٌ أخضر ولا مراجعةُ كود**، بل مستخدمٌ رأى شيئًا أو قياسٌ في متصفّح حقيقي.

## التركيب

استنسخ المستودع إلى مجلّد مهارات المستخدم، فيصير متاحًا في **كل** مشروع على الجهاز:

```bash
git clone <REMOTE_URL> ~/.claude/skills/frontend-playbook
```

ولجعل استعماله حتميًّا لا اعتماديًّا، أضِف القاعدة إلى `~/.claude/CLAUDE.md`:

> قبل كتابة أي كود واجهة أمامية، استدعِ مهارة `frontend-playbook`، واقرأ ملفّ المجال المعنيّ من `rules/` قبل الكتابة لا بعدها.

**نسخةٌ مُفعَّلة واحدة فقط.** أي نسخةٍ مرفوعة أو مُزامَنة من هذه المهارة (كالنسخة المُزامَنة عبر claude.ai) يجب أن يُعاد توليدها من هذا المستودع عند كل تغيير، أو أن تُحذَف. ولا يجوز أن تحمل هذا الاسمَ إلا نسخةٌ مُفعَّلة واحدة — فالنسختان تُستدعيان للطلب نفسه، والإصلاح يصل إحداهما وتبقى الأخرى تُطلِق قواعد بائتة.

وبعد كل إصدار، قارِن كل نسخةٍ مثبَّتة بالمستودع:

```bash
diff -r --exclude=.git --exclude=.gitattributes <INSTALLED_COPY> ~/.claude/skills/frontend-playbook
```

ويجب أن يكون الخرج فارغًا.

## البنية

`SKILL.md` هو نقطة الدخول، وهو الوحيد الذي يدخل السياق تلقائيًّا: يحمل القاعدة الحاكمة، وجدولَ توجيه (أي مهمّة ← أي ملف)، وجدول **«أخطاء تبدو صحيحة»**، وثمانية عشر مبدأً قابلًا للنقل.

وملفّات `rules/` تُقرأ **عند الحاجة فقط** — واحدٌ لكل مجال:

| الملف | المجال |
|-------|--------|
| `starting.md` | الفلسفة الحاكمة، بنية المستودع، قائمة التحقّق التنفيذية للبدء |
| `api-and-state.md` | توليد الأنواع من العقد، العميل المُنمَّط، تطبيع الأخطاء، حالة الخادم |
| `session.md` | المصادقة، الحرّاس، الصلاحيات، صحّة الجلسة عبر التبويبات |
| `tables.md` | محرّك الجداول، والسجلّ الواحد على أسطح متعدّدة |
| `forms.md` | النماذج، واجهات الإعداد المُوجَّهة بسجلّ، الإجراءات الخطرة |
| `i18n-rtl.md` | التدويل، الاتجاه ثنائي الاتجاه، الوقت والمناطق |
| `ui-system.md` | نظام التصميم، العلامة، مكتبة الأنماط المشتركة |
| `layout.md` | مزالق التخطيط والـCSS: الخسارة الصامتة |
| `delivery.md` | البناء، تقسيم الكود، النشر، الأداء |
| `testing.md` | منظومة الاختبار بطبقاتها |
| `accessibility.md` | الوصولية |
| `security.md` | الأمان في الواجهة، ودروس متفرّقة حاسمة |
| `tradeoffs.md` | التقييم النقديّ للتنازلات، وفهرس المزالق |

## مبدأ التحرير

**التقسيم بالمجال لا بالزمن.** لا يوجد في هذه الملفّات حكمٌ خاطئ يُصحَّح لاحقًا: حيث كان هناك حلٌّ ساذج شائع، يُكتب الحكم الصحيح وحده، وتحته فقرة **«لماذا لا يكفي البديل الشائع»** تحفظ التعليل. التعليل هو أثمن ما في الدليل؛ السقالة وحدها هي التي تُحذَف.

**ولا نسخة ثانية.** إن نُسخ محتوى هذه الملفّات إلى مستودع مشروع، انحرفت النسختان بإصلاحٍ واحدٍ في كل مرّة بلا أن يفشل شيء — وهي بالضبط العلّة التي يحذّر منها `tables.md`. هذا المستودع هو المصدر الوحيد، وكل نسخةٍ مثبَّتة أخرى تُعاد توليدها منه أو تُحذَف (انظر «التركيب»).
